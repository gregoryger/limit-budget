# Лимит — AI-помощник по личному бюджету

Интерактивный хакатон-стенд: React + Vite + TypeScript, отдельный TypeScript/Express-сервер. Сайт сразу открывается с вымышленным бюджетом — жюри не нужно загружать файл, вводить реквизиты или настраивать API-ключ. Приложение не подключается к банку и не отправляет деньги.

Визуальная основа — `limit-mockups.html`. Интерфейс включает обзор, сценарии, детектив расходов, цели, подписки, карты и переводы. Демо-цифры явно помечены как вымышленные.

## Быстрый запуск

Нужен **Node.js 22.15+** и npm. Команды выполняются из корня проекта.

```sh
npm ci
npm run dev
```

Открыть **http://127.0.0.1:5173**. Сервер работает на `127.0.0.1:3001`; Vite проксирует `/api`. Расчёты демо доступны без `.env`; для живых советов GigaChat нужен ключ на сервере. Оба сервера привязаны к loopback.

## Показ жюри: всё готово при открытии

1. На **«Обзоре»** сразу видны вымышленные остаток **42 800 ₽**, обязательные платежи **18 497 ₽** и реально свободные **24 303 ₽**. Прогноз на 30 дней учитывает отдельно будущий доход и повседневные траты. Кнопка загрузки выписки необязательна.
2. В **«Сценариях»** спросите GigaChat своими словами. «Куплю телефон за 50 000 ₽» снизит условный прогноз до **6 803 ₽**, «Сниму квартиру за 25 000 ₽ в месяц» — до **31 803 ₽** и покажет годовую стоимость. «Выиграю в казино 500 000 ₽» распознаётся как условное поступление: экран покажет вариант с выигрышем и базовый прогноз без него. Для ответов нужен настроенный серверный ключ; ручной расчёт доступен отдельно.
3. **«Детектив»** покажет мелкие покупки, доставку и такси, а также рост трат на кафе по сравнению с предыдущими 30 днями. Операции, на которых основан вывод, перечислены ниже.
4. В **«Целях»** пример накопления **100 000 ₽** при текущем темпе занимает **8 месяцев**. Поменяйте сумму ежемесячного взноса и сравните три темпа.
5. В **«Подписках»** три регулярных платежа стоят **1 047 ₽ в месяц** и **12 564 ₽ в год**. Отметьте один как ненужный — возможная экономия пересчитается сразу. Реальная подписка не отключается.

Суммы и прогнозы считает код приложения. Если серверный ключ GigaChat настроен, помощник автоматически объясняет текущий раздел и отвечает на вопросы в панели **«GigaChat помощник»**. Кнопки на экранах передают ему рассчитанный сценарий, цель или отмеченные подписки. Ответы модели явно отделены от расчётов. В разделе «Сценарии» GigaChat понимает смысл свободного вопроса, затем сервер считает последствия, и GigaChat объясняет их прямо под вопросом. Без ключа панель показывает инструкцию подключения и не выдаёт локальный текст за ответ GigaChat.

Сборка и запуск собранной версии:

```sh
npm run build
npm start
```

Открыть **http://127.0.0.1:3001**. Сервер отдаёт собранный React-клиент и API. Не запускайте dev-сервер и `npm start` одновременно на одном порту. При изменении `PORT` измените и адрес прокси в `vite.config.ts`.

## Дополнительный сценарий проверки импорта

1. Откройте **«Загрузить выписку»** и нажмите **«Попробовать демо»**, либо загрузите `public/demo-statement.csv`. Для загрузки подтвердите, что данные синтетические или обезличены.
2. Сервер действительно читает файл, извлекает 13 исходных строк и сверяет подготовленный JSON с ними. Баннер явно сообщает, что **импорт этой выписки не вызывал GigaChat**.
3. На экране проверки есть 12 распознанных операций и одна неоднозначная: `Возврат или покупка;450.00;unknown`. Она по умолчанию исключена. Введите причину, например **«Направление неизвестно, исключаю»**. Без решения по каждой строке импорт не подтверждается.
4. Можно исправить дату, сумму, категорию, направление и признак регулярности. Для изменения нужны пояснение и отметка «Я проверил эту операцию». Исходная строка остаётся в журнале. Для включения неоднозначной строки уточните направление и подтвердите её вручную.
5. Нажмите **«Подтвердить импорт»**. Доходы по 12 строкам: **31 500 ₽**, расходы: **11 200 ₽**, разница: **20 300 ₽**, продукты: **4 051 ₽**. Это история операций, а не текущий остаток.
6. Укажите остаток **21 400 ₽**, обязательные платежи **8 900 ₽**, будущие доходы **0 ₽**, ежедневные траты **600 ₽**, дату остатка **25.09.2026**, конец периода **30.09.2026**. Нажмите «Рассчитать прогноз».
7. Доступно после обязательств **12 500 ₽**, впереди **5 дней**, прогноз остатка **9 500 ₽**, условный дневной лимит **2 500 ₽**. Формула: `21 400 − 8 900 − 5 × 600 = 9 500`.
8. В «Переводах» задайте **2 000 ₽**: результат сразу станет **7 500 ₽**. В «Сценариях» выберите **3 000 ₽/день** без разового расхода: дефицит **2 500 ₽**. Исходные операции не меняются.
9. В «Обзоре» доступны категории, вероятные регулярные платежи, подтверждённые операции, исходные строки, допущения и **«Скачать расчёт»** (JSON с журналом исправлений/исключений).

Демо фиксировано на сентябрь 2026 года для воспроизводимости. Дата реального импорта по умолчанию берётся из локального календаря пользователя. Текущий остаток и обязательные платежи всегда вводятся явно, включая `0`, если их нет.

## Подключение GigaChat

Скопируйте `.env.example` в `.env` и заполните **на сервере**:

```powershell
Copy-Item .env.example .env
notepad .env
```

```dotenv
PORT=3001
GIGACHAT_AUTH_KEY=ваш_ключ_авторизации
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Max
GIGACHAT_BASE_URL=https://api.giga.chat/v1
```

`GIGACHAT_AUTH_KEY` — готовый ключ авторизации для `Authorization: Basic`, без префикса `Basic`. Он не является банковским паролем. Не используйте переменные `VITE_*` для ключа. Перезапустите сервер после изменения `.env`. В коде и тестах нет действующих ключей; тесты используют фиктивные значения и подмену HTTP-транспорта.

После перезапуска откройте любой раздел: помощник сделает запрос к GigaChat для краткого анализа. Через плавающую панель можно задать следующий вопрос. Для демонстрационных экранов в модель отправляются только вымышленные данные и проверенные итоги расчётов. [Официальная документация GigaChat по структурированному выводу](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output) описывает используемый формат JSON-ответа.

Адаптер выполняет:

1. OAuth POST `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, `RqUID` UUID v4, `scope` в form-urlencoded; токен кешируется до истечения срока.
2. POST `/v1/chat/completions` с `response_format: { type: "json_schema", schema: ..., strict: true }`. Схема генерируется из общей Zod-схемы, поля обязательны, дополнительные поля запрещены.
3. Парсинг **только JSON** из `choices[0].message.content`, проверку завершённости ответа и Zod-валидацию на сервере.
4. Сверку `sourceId`, суммы в копейках, даты, направления и дословного описания с исходной строкой. Выдуманные или повторные идентификаторы блокируют ответ. Несверяемые операции помещаются на ручную проверку. Пропущенные строки остаются видимыми.
5. После подтверждения — отдельный запрос объяснения **уже рассчитанного кодом** бюджета. Текст объяснения не участвует в арифметике и показывается отдельно от числового результата.

Тайм-аут OAuth — 15 секунд, генерации — 60 секунд. Тела выписок, ключи, токены и ответы провайдера не записываются в логи. TLS проверяется. Команды `npm run dev` и `npm start` запускают сервер с `--use-system-ca`, чтобы Node доверял сертификатам из хранилища Windows. Если окружению нужен дополнительный доверенный сертификат, задайте `NODE_EXTRA_CA_CERTS` с путём к доверенному CA; проверку TLS отключать нельзя.

Без ключа или при сбое API можно пройти **заранее подготовленное демо**. Подготовленный ответ применяется только к совпадающим строкам `demo-statement.csv`. Для произвольного файла без доступного GigaChat сервер возвращает понятную ошибку с предложением демо — чужие строки не заменяются демонстрационными. Кнопка «Попробовать демо» не вызывает провайдера даже при наличии ключа. При загрузке демо-файла с настроенным ключом используется настоящий адаптер; при недоступности API баннер явно сообщает о демо-подстановке.

Параметры проверены по официальной документации 26.09.2026:

- [REST API и авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api) — актуальный адрес `api.giga.chat`, OAuth и scopes.
- [Структурированный вывод](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output) — именно `response_format.schema`, а не OpenAI-обёртка `json_schema`.
- [Работа с файлами](https://developers.sber.ru/docs/ru/gigachat/guides/working-with-files) — изучена; в этой версии файлы не загружаются в хранилище провайдера. Сервер извлекает текст локально и отправляет нумерованные строки, чтобы можно было проверить происхождение каждой операции.

Живой вызов провайдера требует вашего ключа и доступа к API; без ключа проверены HTTP-контракт адаптера через mocks и весь демо-путь через настоящий локальный сервер.

## Формат выписок и ограничения

**CSV:** до **2 МиБ**, **200 непустых исходных строк**, **1 000 символов на строку** и **35 000 символов** суммарно. **PDF:** приложение не ограничивает размер файла, количество страниц, строк или общий объём извлечённого текста. В загрузке проверяются расширение, MIME-тип, сигнатура PDF, UTF-8 и отсутствие нулевых байтов в CSV. Тип из браузера сам по себе не считается доказательством.

**CSV:** UTF-8, допускается BOM, LF/CRLF, разделитель `;` или `,`, CSV-кавычки. Точный заголовок:

```csv
date;description;amount;direction
2026-09-01;Стипендия;+6000.00;income
2026-09-03;Супермаркет;-1250.50;expense
```

- Дата — `YYYY-MM-DD` или `DD.MM.YYYY`.
- Сумма в файле — рубли с максимум двумя десятичными знаками; поддерживаются десятичная запятая и пробелы в тысячах. В CSV с разделителем-запятой значения с запятой нужно заключать в кавычки.
- `direction` — `income` или `expense`; неизвестное направление можно восстановить только по явному знаку `+`/`−` (ASCII `-`). Знак, противоречащий направлению, делает строку неоднозначной.
- Внутри модулей и API **все деньги — целые копейки**. Отрицательных `amountKopecks` нет, знак задаёт `direction`. Каждое входное денежное поле ограничено 100 млн ₽; арифметика укладывается в безопасные целые JavaScript.
- Автоматической поддержки произвольных банковских CSV-заголовков пока нет: приведите файл к указанным четырём столбцам.

**Текстовый PDF:** поддерживается извлечение текстового слоя. Надёжно сверяемый формат строки: `2026-09-03 Магазин -1250.50` или `03.09.2026 Магазин -1250,50 ₽`. Одна операция на строку, дата в начале, одна явно подписанная сумма в конце. Заголовки, несколько денежных колонок, переносы и необычные таблицы остаются видимыми как неоднозначные строки. Их можно исправить вручную или исключить с причиной. OCR, сканы и защищённые PDF не поддерживаются; показывается сообщение об ограничении. Строки PDF передаются в GigaChat порциями до 60 строк/12 000 символов. Строка длиннее контекста одного запроса остаётся видимой для ручного решения. Проверка длинной выписки разбита на страницы по 50 строк. Ограничений приложения на загрузку PDF нет, но обработка всё ещё зависит от доступной памяти сервера и контекста/доступности GigaChat.

Выписка не содержит достаточных данных о текущем остатке и будущих обязательствах: они всегда вводятся отдельно. Регулярность — гипотеза по описанию/повторениям, не достоверное обязательство. Уже прошедшие подписки автоматически повторно не вычитаются.

Прогноз — условная оценка на конец периода. Период начинается **на следующий день после даты остатка**, заканчивается выбранной датой включительно; расчёт дней — в UTC. Будущие доходы и платежи задаются общей суммой, без дат. График учитывает их в начальной точке и **не гарантирует отсутствие кассового разрыва внутри периода**. Резерв и непредвиденные траты учитывайте в обязательствах. Максимальная длина периода — 366 дней.

## Модули и командная работа

| Модуль               | Файлы                                            | Независимая задача участника                                     |
| -------------------- | ------------------------------------------------ | ---------------------------------------------------------------- |
| `statement-import`   | `server/statement-import/`                       | Поддержка новых CSV/PDF-форматов, лимиты и извлечение источника  |
| `gigachat`           | `server/gigachat/`                               | OAuth, промпты, structured output, обработка ошибок API          |
| `transactions`       | `shared/transactions.ts`, `server/transactions/` | Схемы, сверка источника, правила категорий и журнала исправлений |
| `budget-calculation` | `shared/budget-calculation.ts`                   | Чистая арифметика, периоды, допущения, агрегаты                  |
| `scenarios`          | `shared/scenarios.ts`, `src/ui/Scenarios.tsx`    | Что-если, симуляция расходов, сравнение вариантов                |
| `ui`                 | `src/ui/`                                        | Четыре экрана, доступность, мобильная адаптация, форма проверки  |

Входы, выходы, JSON-схема и REST-договор описаны в [docs/CONTRACTS.md](docs/CONTRACTS.md). Сервер — единственный источник подтверждённого импорта; клиент не может передать произвольный массив транзакций в `/api/budget`. Сценарии используют ту же чистую функцию расчёта, что и сервер.

## Тесты

```sh
npm test
npm run build
npm audit
```

Тестируются: разбор реального демо-CSV, извлечение синтетического текстового PDF из байтов, PDF больше 2 МиБ с 21 страницей и 525 операциями, подтверждение такого импорта через API, отсутствие текстового слоя, пустой/неподдерживаемый файл, CSV выше лимита, неоднозначные строки, поддельные ответы модели, OAuth и structured-output HTTP-контракт, точность арифметики, неизвестный остаток, нулевой период, сценарии, HTTP-цепочка загрузки → подтверждения → расчёта.

Браузерные тесты (Playwright):

```sh
npx playwright install chromium
npm run test:e2e
```

Если загрузка браузера недоступна, можно использовать установленный Chrome. В PowerShell:

```powershell
$env:PLAYWRIGHT_CHANNEL='chrome'
npm run test:e2e
```

Тесты поднимают dev-сервер автоматически, проходят сценарий с **настоящей загрузкой файла**, проверяют ручное исправление и семь разделов на мобильном экране, делают снимки в `test-results/`, проверяют отсутствие горизонтального переполнения и работу панели GigaChat с подменённым HTTP-ответом. Папка исключена из Git.

## Данные и Git

- Только синтетические или заранее обезличенные файлы. Не загружайте реальные персональные данные, пароли, SMS-коды, CVV и полные реквизиты.
- Сервер блокирует типичные длинные номера карт/счетов до внешнего запроса. Это дополнительная проверка, **не автоматическое обезличивание**: имена, телефоны и другие персональные данные нужно удалить самостоятельно.
- Файлы обрабатываются из памяти; исходные строки, результаты и аудит живут в памяти сервера до 30 минут, с очисткой раз в минуту. Нет БД, `localStorage` и сохранения загрузок на диск. Перезагрузка страницы возвращает встроенное демо; перезапуск сервера удаляет все импорты. «Вернуть демо» удаляет текущий импорт на сервере.
- `.gitignore` исключает `.env*` (кроме `.env.example`), ключи/сертификаты, CSV/PDF (кроме синтетического `public/demo-statement.csv`), uploads, statements, выгруженные `budget-audit*.json`, логи и сборки.
- Нет авторизации пользователей, постоянного хранения, OCR, реального подключения карт и проведения переводов. Чат отвечает в пределах финансового контекста текущего экрана, а не заменяет консультацию специалиста. Для публичного развёртывания нужны отдельные механизмы авторизации, ограничения запросов и политика хранения данных. Основа рассчитана на локальную демонстрацию.
- Ничего не опубликовано и не отправлено на GitHub.
